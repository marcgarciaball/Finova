# Finova — Progress Board

Status legend: `TODO` · `WIP` · `PARTIAL` (scaffold satisfies part of it) · `BLOCKED` · `DONE` (meets Definition of Done in the spec).

Work one ticket at a time, one PR each. Do not start a phase until the prior phase's gate passes.

> Note: a Supabase + Next.js starter scaffold pre-existed. Tickets already partly satisfied by it are marked `PARTIAL` with a note so the board reflects reality.

> **Naming:** the product is **Finova** — one name everywhere. This board and the product roadmap use it. **Other surfaces may still say "Finvia"** (the design skill, earlier docs, some i18n keys, repo/domain identifiers, the stale `finvia-product-roadmap.md`) and **must be migrated to "Finova"** — track that as cleanup.

> **Tested invariant — money is never a float.** Not just a principle: every monetary amount is **integer cents + an ISO-4217 currency code**, and **no FX rate is ever invented** (cross-currency consolidation is refused; the user sees per-currency totals until a real rate source exists). This is enforced by the pure money module `lib/domain/money/` and its tests — see [`lib/domain/money/money.test.ts`](lib/domain/money/money.test.ts) (constructors, exact arithmetic, no-float guarantees) and `format.test.ts`; the totals/dashboard cores (`summarizeInBase`, `accountBalances`) `throw` rather than guess a missing rate.

**P2-01 fix (2026-06-29):** browser testing surfaced that `uploadImport` returned a client-generated `batchId` (used for the storage path) while the inserted `import_batches` row got a *different* DB-default `id` — so `reviewBatch`/`commitBatch` (`.eq('id', batchId)`) always failed with `batchNotFound` ("No encontramos esa subida"). **P2-08 fix (2026-06-29):** browser testing then surfaced that **Commit failed every row** ("N filas fallaron"). Root cause: `commitBatch` upserts with `onConflict: 'user_id,import_fingerprint'`, but `0006` created that as a **partial** unique index (`WHERE import_fingerprint is not null`). Postgres can't infer a partial index for `ON CONFLICT` without its predicate, and PostgREST never sends one → 42P10 on every chunk. Fixed by making the index **non-partial** (`lib/db/schema/transactions.ts`; NULLs are distinct by default so manual rows stay unconstrained) + migration `drizzle/0009_jittery_agent_brand.sql` (drop partial, create full unique index, both `IF [NOT] EXISTS`). **Action required:** `npm run db:migrate` to apply `0006`–`0009`. This is the integration gap the manual gate is meant to catch — the idempotency RLS test exercises the index but is skipped without `TEST_DATABASE_URL`.
